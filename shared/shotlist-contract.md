# Контракт шот-листа

`clip-memory/script/shotlist.json` — стык творческой и производственной частей. Слева от него
сценарий и режиссура, справа — промпты и деньги. Поэтому формат жёсткий: его читает
`gate_script.py`, а не человек.

## Схема

```json
{
  "project": "NAME",
  "form": "concept | narrative | performance | hybrid",
  "lyric_relation": "illustrate | counterpoint | independent",
  "change": "одной фразой: что меняется от первого кадра к последнему",
  "shots": [
    {
      "id": "S01",
      "section": "intro",
      "beats": 8,
      "size": "EWS",
      "angle": "eye",
      "movement": "push_in_slow",
      "anchors": ["room", "lamp"],
      "content": "пустая комната, пыль в луче света",
      "light": "одно окно слева, золотой час",
      "note": "установка мира: где мы и по каким законам тут живут",
      "enabled": true
    }
  ]
}
```

## Поля

| Поле | Обязательно | Значения |
|---|---|---|
| `form` | да | одна из четырёх форм (`shared/cinema/01-music-video-forms.md`) |
| `lyric_relation` | да | отношение к тексту песни, одно на весь клип |
| `change` | да | если не формулируется — замысла нет |
| `reality` | нет (умолчание `real`) | регистр: `real`, `heightened`, `fantasy` (`shared/cinema/12-reality-register.md`); у кадра — переопределение |
| `miracle` | да, если `reality` не `real` | одной фразой: какое допущение и по каким законам; у кадра — своё, иначе клипа |
| `id` | да | `S01`, `S02`… сквозная нумерация |
| `section` | да | имя раздела из `song/grid.json` |
| `beats` | да | длина плана В ДОЛЯХ, целое ≥ 1 |
| `size` | да | `EWS`, `WS`, `MS`, `MCU`, `CU`, `ECU` |
| `angle` | да | `eye`, `low`, `high`, `bird`, `dutch` |
| `movement` | да | `static`, `push_in_slow`, `push_in_fast`, `pull_out`, `tracking`, `pan`, `tilt`, `handheld` |
| `anchors` | да | имена якорей из `canon.refs`; пустой список допустим только с `"anchors_free": true` |
| `content` | да | что происходит в кадре, одной фразой; словами описывается только то, чего якорь не держит |
| `light` | да | источник и направление, не настроение |
| `note` | да | зачем этот кадр стоит здесь; пустое поле = кадр лишний |
| `src` | да, если планов больше, чем генераций | имя источника: `frames/<src>.png` → `clips/<src>.mp4`. Несколько планов на один `src` — норма (R20: один снятый источник даёт несколько планов) |
| `enabled` | нет | по умолчанию `true` |

Рядом с `shots` живёт словарь `sources`: `src → { "desc": "...", "shots": ["S01", "S03"] }`.
У источника может стоять `preset` (`oner`, `title_reveal`) — тогда его движение собирает
`preset_build.py` из полей (R34), а доли одного источника делятся между несколькими кадрами.
`desc` одной фразой описывает, что заказано у источника, — это подпись на контактном листе
приёмки (R31). Без `src` и `sources` сверка ролика со сценой не собирается: приёмке нечего
положить рядом с роликом, и она снова оценит картинку вместо сцены.

## Что проверяет `gate_script.py`

1. **Сходимость с треком** — сумма `beats` × длительность доли = длина трека ±1 такт.
   **Формат hook** (ролик под фрагмент, например Suno-hook): окно записано в `song/grid.json` →
   `hook.start` / `hook.end`, секунды трека. Тогда сумма сверяется с длиной окна, а `section`
   каждого кадра обязан пересекаться с окном. Подсказки музыковеда (`recommended_*`) окном не
   считаются; окно с одним полем или за концом трека — отказ. Маркер получает `format: "hook"`.
2. **Разделы существуют** — каждый `section` есть в `song/grid.json`.
3. **Якоря существуют** — каждое имя из `anchors` есть в `canon.refs` или в `anchor-brief.json`
   как запланированное; ссылка на несуществующий якорь — блокер.
4. **Монтажная читаемость** — у соседних кадров не совпадают одновременно `size` и `movement`.
5. **Полнота** — нет пустых `note`, `content`, `light`.
6. **Развитие** — припевы не идентичны: у второго припева хотя бы одно поле отличается от первого.
7. **Словарь** — значения `size` / `angle` / `movement` только из списков выше.
8. **Источники** — `src` либо у всех кадров, либо ни у кого; каждый `src` есть в `sources`
   с непустым `desc`. Половина шот-листа с источниками, половина без — это разъезд имён
   между кадрами, роликами и вердиктами, и на нём слепнет гейт сверки (R31).
9. **Герой** (только `form` = `narrative` или `hybrid`) — файл `clip-memory/script/hero.json` с
   четырьмя непустыми полями. **Предупреждение, не провал:** печатается строкой `[~]`, маркер
   `script-ok` пишется. Формат ниже.

Провал — exit 2 и текст, какие кадры виноваты. Чинится шот-лист, не скрипт.

## Герой: `script/hero.json` (необязательный)

Мнемоника «станция» — сокровище, тайна, недостаток, цель
(`shared/cinema/08-dramaturgy-short-form.md`). Ключи — латиницей, значения — по-русски, одной фразой:

```json
{
  "treasure": "уникальная черта, талант или статус",
  "secret":   "скрытый секрет или прошлое",
  "flaw":     "слабость, уязвимость, порок — то, за что берут в заложники",
  "goal":     "к чему герой стремится внутри ЭТОЙ истории"
}
```

Герой, которого не записать в четыре строки, ещё не придуман — отсюда предупреждение. Не стоп:
нарративный клип Bravo прошёл гейт 18.09.2026 без героя, и новое требование не должно
задним числом ломать пройденное.

## Чего гейт НЕ проверяет намеренно

**«Одинаковая крупность через один»** (A–B–A). Правило годится для коротких форм,
но замер на шот-листе Bravo (89 планов) дал 30% троек по крупности и 17% по трём
параметрам сразу: для клипа это обычное чередование, предупреждение читалось бы как шум.
Вернётся в рекламный гейт, где планов 3–5 (`shared/ads/02-plan.md`).

## Как из строки собирается промпт

```
content + size + angle + movement + light + style из канона + must из канона
+ ссылки на anchors (картинками, НЕ словами — R01)
- всё, что попало в canon.silence (R02)
```

Промпт-инженер не добавляет ничего от себя. Если для кадра не хватает данных — возврат
раскадровке. Досочинённое в промпте не попадает в паспорт и теряется при пересъёмке (R13).
