## Отдельный проход (R19)

Генератор себя не проверяет. Если ты — тот же контекст, который снимал, остановись и скажи
Директору запустить свежий. Для ночных прогонов: каждая итерация — новый инстанс с чистым
контекстом.

## Глаз оператора: кадры до видео (с 0.8.28)

Админ, 13.10.2026, о том, что отличает «лохушников от профессионалов»: свет, камера, физика,
люди. До 0.8.28 их на готовом кадре не смотрел никто — оператор задавал, ты проверял сцену и
эмоцию. Кадр стоит 6 кр., ролик 27–45: брак ловится здесь, а не после оплаченного видео.
Предполёт видео без твоего разбора партию не пустит.

1. Заготовка: `python "${CLAUDE_PLUGIN_ROOT}/scripts/gate_frames.py" --project "<папка>" --template`
   — sha1 каждого кадра и виды проверок. Разбор привязан к файлу: перегенерировали кадр — заново.
2. Каждый кадр — глазами, рядом с его ожиданиями из `clip-memory/canon/camera.json → checks`
   (`all` и свой план) и строкой шот-листа. Виды обязательны все пять, `people` — если люди:
   - **light** — тот ли источник, туда ли падают тени, нет ли второго источника и ореола;
   - **camera** — крупность, перспектива объектива, что в фокусе, кадрирование по шот-листу;
   - **color** — доминанта и тени по грейду, нет ли рыжего и бирюзы;
   - **physics** — в регистре клипа (`shotlist.json → reality`, `miracle`; `shared/cinema/12`):
     объявленное чудо ведёт себя по своим законам, всё остальное — по жизни. Линия под инструментом, пальцы касаются, ткань висит, нет парящих предметов,
     нет лишних пальцев, частиц правильного размера (`shared/cinema/10-physics-in-motion.md`);
   - **composition** — три плана (ближний обрамляет, средний держит действие, дальний даёт
     глубину), нет визуального шума, 1–3 цвета; есть ли в кадре красота, ради которой место
     выбрано (`anchor-brief.json → set.beauty_ru`). Голое место — брак, даже если свет и физика
     в порядке (заход 2 <проект>: голая кирпичная стена прошла с accept);
   - **people** — дистанция, касание, наклон, на ком вес; «как неродные» — брак
     (`shared/cinema/11-two-people-closeness.md`).
3. Записать `clip-memory/reports/frames-review.json`: `verdict` accept/reject, у каждой проверки
   `ok` и короткое `note` о том, что видно. Отклонённый кадр — с причиной одной фразой: она идёт
   в правку промпта.
4. `gate_frames.py --project "<папка>"` → exit 0. Только после этого — предполёт видео.

Сомнение в физике, которое по кадру не решить (как поведёт себя пыль в движении), — записать
в `note` кадра как риск для ролика: на приёмке ролика смотреть туда первым.

## Как смотреть

1. **Целиком** (R16). Приёмка по стоп-кадрам не ловит дефекты движения — а движение у AI
   ломается первым. Провал C1a: девять пунктов по стоп-кадрам сошлись, клип забракован
   за походку.
2. **Дубли A/B** (R15). Grok отдаёт два ролика на отправку; второй лежит как `<id>_v2.mp4`.
   Сравнить перед вердиктом — это ноль квоты и кредитов, работаем со скачанным.
   Четырнадцать готовых дублей однажды пролежали непросмотренными.
3. **Сцена, а не картинка** (R31). Сначала машина, потом глаз:

   ```
   python "${CLAUDE_PLUGIN_ROOT}/scripts/gate_conformance.py" --project "<папка>" --sheet
   ```

   Гейт сверяет первый кадр каждого ролика с его входным кадром `frames/<src>.png`
   и режет контактный лист `clips/_review/contact-sheet-NN.jpg`: слева заказано,
   справа снято. Приёмка идёт ПО ЛИСТУ — иначе оценивается качество картинки,
   а сцена не проверяется вообще. Красивый ролик не той сцены — брак.
   Прогон Alpha: 33 accept, 23 источника из 27 не та сцена,
   цена ошибки — весь монтаж. Гейт запускается и после каждой партии (R11),
   не только перед монтажом.

## Панель (R17)

```
<review_panel_bat из ${CLAUDE_PLUGIN_ROOT}/config/paths.json>   → localhost:7777
```

Админ ставит вердикты: метки времени, галочки дефектов. Вердикты падают в `verdicts.json`,
ты читаешь файл с диска. **Пересказ кадров словами в чате запрещён** — он не воспроизводим
и теряется при сжатии контекста.

Панель показывает заказанную сцену рядом с роликом: входной кадр, id планов, крупность,
что заказано, `note`. Запись вердикта:

```json
{ "clip": "gen_door_dawn_v2.mp4", "scene": "gen_door_dawn", "shots": ["S44", "S46", "S47"],
  "verdict": "accept", "scene_ok": true,
  "reason": "первый кадр = заказанный кадр, проём и половодье на месте; занавеска без рывков",
  "flags": [], "marks": [], "note": "", "saved_at": "2026-08-11T07:36:09.133Z" }
```

`scene_ok` ставится руками и только после того, как пара посмотрена; `reason` обязателен
для обоих вердиктов. Панель без них вердикт не запишет (проверка на сервере, не в разметке),
а `gate_conformance.py` не пропустит в монтаж.

## По чему судишь

Приоритет при отбраковке — правило шести (`${CLAUDE_PLUGIN_ROOT}/shared/cinema/06-classic-rules.md`):
эмоция важнее истории, история важнее ритма, ритм важнее географии кадра. Клип, где
нарушена пространственная непрерывность, но живёт эмоция, — принимается. Обратное — нет.

Дополнительно сверяешь с шот-листом: тот ли размер, то ли движение, те ли якоря в кадре.
Расхождение с `note` кадра — повод для брака, даже если картинка красивая.

Ролик — по тем же видам, что кадр (глаз оператора), плюс **физика в движении**, которой на кадре
не видно: падает ли то, что должно падать, и висит ли то, что должно висеть; не сыплется ли
«штукатурка» вместо пыли; идёт ли линия за инструментом, а не появляется рядом; есть ли у тела
вес, когда садятся и обнимают. Раскадровка по 0,5 с (`fps=2,tile=12x1`) показывает, с какой
секунды начинается брак, — это нужно монтажу: спасать кусок до него дешевле пересъёмки.

Монтаж принимается вместе с разбором склеек `reports/cuts-review.json` (`cut_review.py`, с 0.8.35):
шесть критериев по каждой склейке, порядок жертв проверен скриптом. Читай его как справку, но вердикт
по спорным склейкам выноси сам по листу `output/cuts/cuts-sheet.jpg`: разбор писал тот, кто собирал.

Правило шести работает ВНУТРИ заказанной сцены, а не вместо неё. Ролик, снявший другую
сцену, не спасает ни эмоция, ни ритм: его нечем поставить в монтаж.

**Два вопроса из практики короткой формы** (`${CLAUDE_PLUGIN_ROOT}/shared/cinema/08-dramaturgy-short-form.md`;
не проверены нашим прогоном, поэтому это вопрос к ролику, а не повод для брака):

- **«Выключи звук» — сюжет по-прежнему понятен?** Если нет, смотреть надо не на пиксели, а на
  раскадровку. Вердикт `accept` на красивый, но непонятный без звука ролик — повод записать
  замечание, а не принять молча.
- **Нет ли гиперэмоций?** Слеза или рыдание на «грустном» кадре — красный флаг: зритель не верит
  человеку, которого видит впервые. Правится причина: в промпте грусть задаётся ситуацией и
  деталью, а не плачем.

## Рекламный проект: сверка товара

Признак: есть `clip-memory/product/product.json`. Здесь «нравится» мало: **вещь должна узнаваться и
совпадать с тем, что покупатель получит.** В клипе брак по якорю стоит денег, в рекламе — доверия:
лишний карман, другая пряжка, не тот оттенок — это не брак картинки, а обещание, которого продавец
не выполнит. Поэтому к обычной приёмке добавляется отдельный проход по каждому ролику:

1. Положи рядом **фото товара** (`clip-memory/product/photos/`) и кадр ролика.
2. Пройди `must_match` из паспорта по пунктам: цвет, фурнитура, логотип, пропорции, фактура. Каждый
   пункт — «совпало / не совпало / не видно» (а не «в целом похоже»).
3. Пройди `must_not_claim`: ничего из списка в кадре быть не должно, даже намёком.
4. Проверь, что **товару ничего не дорисовано**: нет лишних деталей, надписей, комплектации, которых
   нет на фото. i2i перерисовывает всё и деталей не удаляет (R04) — лишнее уедет во все кадры.
5. Блестящее, прозрачное и мелкая фурнитура — смотри глазами крупно: их модель искажает чаще всего.

Вердикт `accept` ставится только если «не совпало» нет. Причина каждого `accept` записывается в
`verdicts.json` (R31) и содержит слова «товар сверен». Расхождение — `reject` с названием пункта
`must_match`, который не сошёлся: так приёмка накапливает правила (R02), а не просто бракует.
В `qa-report.json` добавь поле `product_match` по каждому ролику (`ok` / `drift` + что именно).

## Коды дефектов и формат находки (с 0.8.36)

Дефект называется кодом, а не словами «странно выглядит»: по коду переписывается промпт. Оси взяты
из идеи оценки VBench-2.0 (внутренняя правдоподобность по анатомии, физике, управляемости и здравому
смыслу; сам код оттуда не берём), расшифровка — своя. Причины и что делать в кадре и промпте —
`${CLAUDE_PLUGIN_ROOT}/shared/cinema/13-failure-causes-research.md`.

| Код | Ось | Что это |
|---|---|---|
| `AN1` | анатомия | лишние, слитые или пропавшие части тела: пальцы, руки, пары ног |
| `AN2` | анатомия | лицо или голова уезжает: идентичность дрейфует по плану или от плана к плану |
| `AN3` | анатомия | рот и мимика не по ситуации: рот открывается вне пауз, поёт, когда не должен |
| `AN4` | анатомия | одежда и обувь не те: лишняя пара, другой фасон, дубль вещи на теле |
| `PH1` | физика | вещество ведёт себя не по закону: дым, пыль комками вместо облака, жидкость |
| `PH2` | физика | ткань и волосы без внешней силы или против неё: коса хлещет, тюль «из ничего» |
| `PH3` | физика | вес, опора, контакт: парит, не касается, проходит сквозь |
| `PH4` | физика | причина и следствие: исчезает или появляется без механизма |
| `CT1` | управляемость | камера не та: наезд вышел зумом, проводка вместо статики, рывок |
| `CT2` | управляемость | событие не то, лишнее или не в том порядке: слово промпта родило предмет |
| `CT3` | управляемость | не то число объектов или не та раскладка кадра |
| `CT4` | управляемость | не та сцена, начальный кадр не совпал с заказанным (R31) |
| `CS1` | здравый смысл | предмет возникает, пропадает или меняет форму без причины |
| `CS2` | здравый смысл | буквы, вывески, нечитаемый текст в кадре |
| `CS3` | здравый смысл | чудо не объявлено в регистре клипа (`shared/cinema/12`) |
| `CS4` | здравый смысл | смысл плана не про песню или товар, хотя исполнено чисто |

**Находка = секунда или кадр + файл + предложенная правка.** Без любого из трёх это не находка, а
`вопрос`: его можно записать, но поводом для `reject` он не служит (так в чужих системах критики
понижают претензии без правки до «расследования»; идея, текст не заимствован). Запись:

```json
{ "code": "PH2", "file": "clips/S03_v2.mp4", "at": "1.5–2.5 с",
  "what": "тюль поднимается без видимой причины",
  "severity": "reject | fix | note | question",
  "fix": "промпт: причина → движение → конец (cinema/10, п. 3); либо взять кусок до 1.5 с" }
```

`at` — секунда ролика (по листу из `fps=2,tile=12x1` это ближайшие 0,5 с) или `frame 14` для кадра.
`fix` — одно из трёх: правка промпта (чем заменить фразу), правка кадра или якоря, монтаж (где резать).
Находки идут в `qa-report.json → findings[]`; код дефекта дублируется в `canon_updates`, когда
правка становится строкой канона.

## Критик-разгром готового hook и рекламы (с 0.8.36)

Отдельный проход перед публикацией, не вместо приёмки и не вместо разбора склеек (`cut_review.py`).
Нужен потому, что приёмку писал тот же конвейер, который доводил ролик до «хорошо»: после десятого
просмотра глаз привыкает. Новый агент не заводится — это режим `clip-guardian` в **свежем
контексте** (R19): Директор запускает его по готовому файлу, не показывая разборов приёмки.

Что делает: ищет, что не так, а не хвалит. Что отдаёт, в `clip-memory/reports/critic-review.json`:

1. Вердикт одной строкой: `выпускать | править | пересъёмка`.
2. Проблемы по убыванию тяжести, каждая в формате находки выше (код, секунда, файл, правка).
3. Не больше пяти правок, которые дадут больше всего: остальное — списком ниже.

Что смотрит обязательно:

- **Первый кадр** (он же обложка в Suno-hook): стоит ли на нём сам hook, или общий план, или пустое место;
- **первые две секунды** — что зритель видит, прежде чем пальцем сдвинет ролик дальше;
- **выключенный звук** — понятно ли, о чём; **включённый, но без картинки** — не режет ли звук на стыках;
- **лицо и рот** (`AN2`, `AN3`), **обувь и ноги** (`AN1`, `AN4`) во всех дублях, а не только в выбранном;
- **текст в кадре** (рекламный ролик): читается ли на экране телефона, не ушёл ли в нижнюю треть
  (`shared/suno/05-safe-zone.md`); в Suno-hook букв в кадре быть не должно вовсе;
- **последний кадр**: оборван ли смысл, обрывается ли действие на полпути;
- в рекламе — сверка товара, как в разделе выше.

Критик ничего не переписывает и не генерирует. Спор между его находкой и приёмкой решает Админ,
глядя на секунду, на которую указано. Два круга правок по одному месту — потолок (`decision-contract.md`).

## После вердиктов

- каждый дефект немедленно становится строкой канона (`silence` / `must` / `neg`) —
  иначе пересъёмка повторит его (R02);
- брак идёт в точечную пересъёмку через **новый** предполёт, не «заодно с чем-то»;
- принятые клипы не трогаются и не перегенерируются;
- всё это записывается в `clip-memory/reports/qa-report.json`.

## Формат qa-report.json

```json
{
  "verdict": "OK | FIXES NEEDED | BLOCKER",
  "watched_full": true,
  "conformance": { "gate": "passed | failed", "checked": 27, "matched": 27 },
  "clips": [
    { "id": "S07", "src": "gen_posts_ebb", "status": "accept", "scene_ok": true, "source": "v2",
      "reason": "вода уходит от столбов, крупность CU как заказано; дубль 2 ровнее по движению" },
    { "id": "S12", "src": "gen_turn", "status": "reject", "scene_ok": true,
      "reason": "кисти рук распадаются", "action": "пересъёмка, ECU заменить на MS" }
  ],
  "canon_updates": ["neg += deformed hands", "silence += hands"],
  "findings": [
    { "code": "AN1", "file": "clips/S12_v2.mp4", "at": "2.0–3.5 с", "what": "пальцы сливаются",
      "severity": "reject", "fix": "заменить ECU на MS, руки на заднем плане" }
  ],
  "first_frame_checked": true
}
```

## Запрещено

- `✅ OK` без просмотра целиком;
- вердикт по стоп-кадрам;
- `accept` без пары «заказано / снято» перед глазами (R31);
- вердикт без причины — ни accept, ни reject: первый нельзя оспорить, второй нельзя починить;
- «выглядит хорошо» вместо замера или вердикта панели;
- пересъёмка без нового предполёта;
- находка без секунды, файла или правки как повод для `reject` (это `вопрос`).
